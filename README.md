# 南京理工大学课程大纲 · 离线快照

从南京理工大学教务系统「课程总库」抓取的离线快照，纯静态站点，无后端、无数据库。

```
index.html              索引页（搜索 / 筛选，读 index.json）
index.json              全量索引，12 991 条
html/<编号>.html        每门课一个页面（重新排版，便于阅读与打印）
json/<编号>.json        每门课一份结构化数据
txt/<编号>.txt          每门课一份纯文本（Markdown 语法）
original/<编号>.html    源系统抓取的原始页面，原样保留未作改动
```

`<编号>` 即教务系统的课程编号（8 位字母数字，如 `10063001`）。
除 1 门编号为空的课程以 `seq1` 命名外，其余均可用编号直接定位。

## 部署

纯静态，整个目录直接托管即可。

GitHub Pages 官方限制（见 docs.github.com 的 GitHub Pages 限制页）：

| 限制 | 值 |
|---|---|
| 源仓库体积 | 建议 1 GB 以内 |
| 已发布站点 | 不得大于 1 GB |
| 部署耗时 | 超过 10 分钟会超时 |
| 带宽 | 软限制 100 GB / 月 |
| 构建频率 | 软限制 10 次 / 小时 |

本站根目录已带 `.nojekyll`，Pages 会跳过 Jekyll 构建、直接原样发布。
从分支发布时 Pages 默认会跑一遍 Jekyll，4 万个文件逐个扫描有撞 10 分钟超时的风险，
加这个文件是最省事的规避方式。

## 编码

全部文本产物统一 UTF-8，但 BOM 策略不同：

| 目录 | BOM | 原因 |
|---|---|---|
| `txt/` | 有 | 服务器若不给 `charset`，浏览器和记事本会按 GBK 猜，中文全乱码 |
| `original/` | 有 | 原件里的声明是 `pageencoding="UTF-8"`（非法属性），浏览器不认 |
| `json/` | **无** | JSON 标准不允许 BOM，`JSON.parse` 遇 BOM 直接报错 |
| `html/` | 无 | 已用 `<meta charset="utf-8">` 声明 |

直接双击本地文件、或用普通静态服务器（不返回 `charset`）打开时，
`txt/` 与 `original/` 的 BOM 能保证中文不乱码。

## 数据修正记录

生成时修正了源快照中的两处问题：

1. **学时字段错位**。原始快照里 `lecture_hours` / `lab_hours` / `pc_hours`
   取成了「第一章」的学时（1179/1179 份完全吻合），导致如「数据结构」显示
   总学时 32、讲课学时 2。现已改为从章节表汇总。`total_hours` 本身正确，予以保留。
2. **重复与空编号**。`04069401`、`71001701` 各有两条重复记录（源系统重复录入），
   已合并为一条；1 门课程编号为空，文件以 `seq1` 命名。

`original/` 下的原始页面未做任何修改，与教务系统返回的 HTML 完全一致，
可用于核对重新排版后的 `html/` 版本是否有信息丢失。
